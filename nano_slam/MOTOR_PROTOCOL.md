# J1 步进电机串口协议 v1

这是本项目新定义的协议。已实现 Nano 端编码、接收校验、短行程测试工具，以及可移植的 C++ 板端状态机。现有 CH340 USB 设备不会自动支持这套协议；必须先让驱动板主控固件实现它。

当前状态（2026-11-22）：已按所提供原理图和用户确认的 10V 编码器直流电机烧录 DC 有限测试镜像，并完成两路 PWM 点动、编码器反馈与停车读回测试。没有发送步进 JOG/WHEELS，没有改动 ROS 的实车 `/cmd_vel` 接线。实际结果见 `firmware/stm32f103rc_comm/DC_BENCH.md`。此前通信专用版仍作为独立构建配置保留，ARM 返回 UNBOUND；当前实际运行的 DC 测试版则在显式 ARM 后允许受限 PWM。

## 1. 串口与帧

- 115200 baud，8 数据位、无校验、1 停止位，无硬件流控。
- ASCII 帧，以 `$` 开头、LF 结束；允许 CRLF。完整帧最多 160 字节。
- 格式：`$J1,会话号,序号,命令,参数...*CRC\n`。
- CRC 为 CRC-16/CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，不反射，最终不异或。计算范围是 `$` 后、`*` 前的全部 ASCII 字节，不含 `$`、`*`、换行。CRC 输出为 4 位大写十六进制。
- 校验向量：ASCII `123456789` 的 CRC 为 `29B1`。
- 会话号和序号均为十进制整数 `1..4294967295`。每次新连接使用不同的随机会话号；同一会话内序号递增，不能回绕。
- 参数只使用整数；不要加入空格、浮点小数或中文。

以下是工具实际生成的完整帧，展示会话号为 1 的一次点动流程。每行末尾必须发送换行字节，不是反斜杠加字母 n：

```text
$J1,1,1,HELLO*4FA5
$J1,1,2,STATUS*F619
$J1,1,3,ARM*EC72
$J1,1,4,JOG,0,50,100*F881
$J1,1,5,STOP*BBBB
```

点动期间还需要每约 100 毫秒发送新的 `KEEP` 指令，序号随之递增。因此上面的 5 行只是字段和 CRC 示例，不能作为完整的实时发送脚本。

## 2. 命令

- `HELLO`：建立会话，不启动、不使能电机。已有电机使能时拒绝另一个握手。停止后的旧会话不能直接恢复运动，需要新会话。
- `STATUS`：读取状态，不延长运动超时。
- `ARM`：请求使能。要求固件已经绑定电机硬件接口、硬件健康、急停释放、状态为 DISARMED。上电默认 DISARMED。
- `JOG,轴号,有符号脉冲数,频率`：有限脉冲点动。例如 `JOG,0,50,100` 为轴 0 发送正方向 50 个脉冲，目标频率 100 脉冲/秒。轴号为 0 或 1；脉冲数绝对值 1..200；频率 1..200 脉冲/秒；名义时长不得超过 1.5 秒；板端绝对运行上限为 2 秒。方向电平和轴接线由硬件适配层定义。
- `KEEP`：续期已使能空闲状态或正在执行的有限点动。不能延长旧的连续速度指令。
- `WHEELS,轴0频率,轴1频率`：两个轴各自的有符号脉冲频率，均为 -200..200 脉冲/秒。初始按差速模型预留两轴，但实际车轮数量、接线和正方向尚未确定。运行时必须约 10 Hz 持续下发新的 WHEELS，不能只发一次再用 KEEP 保持。
- `PWM,轴号,有符号占空比千分数,持续毫秒`：可选的直流电机有限测试命令，例如 `PWM,0,200,250` 为 Motor1 的 20% 占空比、250 毫秒。占空比绝对值 1..200，持续时间 1..400 毫秒，需先 ARM，运行中以 KEEP 续期。仅已明确编译直流测试硬件适配的固件支持；JOG/WHEELS 的脉冲单位不改变。板端绝对上限 500 毫秒；状态为 PWM_TEST，不能插入连续速度命令。默认通信固件仍拒绝使能。
- `STOP` / `DISARM`：立即清除待发脉冲、停止硬件脉冲定时器并禁用电机输出，撤销当前会话。若已经急停或故障，保持相应锁存状态。
- `ESTOP`：停止并锁存软件急停，撤销会话。
- `CLEAR`：急停输入已释放且硬件健康时，清除急停/故障锁存并回到 DISARMED；不会使能或恢复旧运动，同时撤销当前会话。

STOP、DISARM、ESTOP 在 CRC 正确时允许从其他会话或使用旧序号请求停止。它们只会停止，不会使电机运动。会话号用于关联回复和防止意外重放，不是身份认证；CRC 不是安全认证。需要不可信网络访问时，应在更外层做访问控制。

## 3. 回复与状态

成功回复体：

```text
J1,会话号,序号,ACK,原命令,状态,已绑定,已使能,忙
```

`已绑定`、`已使能`、`忙` 为 0 或 1。外层同样带 `$`、CRC 和换行。这里的“忙”表示硬件层报告仍有运动任务，不是实际轮速测量。

失败回复体：

```text
J1,会话号,序号,ERR,原命令,错误码
```

错误码包括：`SESSION`（会话不符）、`SEQ`（乱序或序号重复但内容不同）、`STATE`（状态不允许）、`RANGE`（超出测试范围）、`UNBOUND`（未绑定板卡硬件）、`INTERLOCK`（急停/健康条件不满足）、`HAL`（硬件调用失败）、`BUSY`（使能中不能换会话）、`COMMAND`（未知命令或参数数量不符）。CRC 错误、无法解析或过长的报文直接丢弃，不发送运动、也不续期。

状态为 `DISARMED`、`ARMED`、`RUNNING`、`JOGGING`、`ESTOP`、`FAULT`。板端状态与 `STATUS` 是最终依据；重复报文可能返回原先缓存的 ACK，缓存 ACK 不是实时状态快照。

可选 DC 测试新增 `PWM_TEST` 状态。其电机通道和方向只由与原理图一致的硬件适配决定，不代表步数、角度或转速。

同一会话中，最近一条请求若序号和内容完全相同，只返回缓存回复，不重复执行，不续期。这一点避免点动请求的重复执行。较旧序号拒绝。Nano 工具遇到响应超时不会自动重发运动命令。

## 4. 停车规则

- 上电、复位默认禁止电机输出。
- ARM 后以及运动中，300 毫秒未获得有效运动续期，停止并禁用输出、撤销会话。STATUS、错误帧、重复帧都不能续期。
- RUNNING 只能由新的有效 WHEELS 续期。JOGGING 使用新的 KEEP 续期，但无论 KEEP 是否持续，2 秒绝对上限仍生效。
- 有效 STOP / ESTOP、硬件急停输入、硬件健康故障立即终止脉冲输出。
- 单片机必须持续调用 `tick()`，建议主循环最大间隔不超过 1 毫秒，定时器中断负责稳定的 STEP 脉冲。软件挂死时，还需硬件看门狗、驱动器默认禁用电平和独立硬件急停承担最后保护。
- 当前初始低频和短行程限值属于协议测试参数，不能代替具体电机的电流、脉宽、加减速和机械限制配置。

## 5. 文件与适配

- `scripts/motor_link.py`：Nano/电脑端 CLI，兼容 Python 2.7 和 Python 3，默认仅打印报文，不打开串口。
- `firmware/j1_protocol_demo/j1_protocol.h`、`.cpp`：不依赖 Arduino API 的板端解析、会话、限值、急停与超时状态机。
- `firmware/j1_protocol_demo/j1_protocol_demo.ino`：Arduino 风格接入示例。默认 `UnboundMotor.ready()` 返回 false，ARM 必须报 UNBOUND；没有猜测任何引脚，也不能发出真实电机脉冲。此 .ino 尚未针对实际芯片工具链编译或烧录。
- `tests/protocol_board_tests.cpp`：原生模拟硬件测试与伪串口对端，不能控制物理电机。
- `tests/test_motor_protocol.py`：Python 编解码、收发和跨语言联调测试。

实际驱动板需要实现 `MotorHal`：硬件就绪与健康状态、急停输入、输出使能、立即取消脉冲、两轴速度、有限脉冲点动、任务是否仍忙。`stop()` 和 `enable(false)` 必须停止脉冲定时器并清空任务，不能仅修改目标速度。控制器构造前应先将真实电机引脚初始化为禁用状态；部分 USB 串口开发板在打开串口时可能复位，复位路径同样应默认禁用。

确定主控芯片与 STEP/DIR/EN 引脚、有效电平和驱动器脉宽后，才能编译板卡固件并烧录。CH340 本身不能提供这些信息。

## 6. Nano 端使用

现在可以执行的默认预览：

```bash
python ~/slam_ws/src/nano_slam/scripts/motor_link.py jog --axis 0 --steps 50 --rate 100
```

下面命令仅用于驱动板已实现、烧录并验证 J1 后；本次没有执行它们。端口使用已经枚举到的固定路径，不会自动选择雷达串口：

```bash
PORT=/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0

# 握手并读取硬件绑定和输出状态
python ~/slam_ws/src/nano_slam/scripts/motor_link.py --send --port "$PORT" status

# 工具自动依次握手、确认绑定、ARM、点动、约 10Hz 续期、STOP
python ~/slam_ws/src/nano_slam/scripts/motor_link.py --send --port "$PORT" jog --axis 0 --steps 50 --rate 100

# 独立停止 / 锁存急停
python ~/slam_ws/src/nano_slam/scripts/motor_link.py --send --port "$PORT" stop
python ~/slam_ws/src/nano_slam/scripts/motor_link.py --send --port "$PORT" estop

# 急停释放后清除锁存；清除本身不运动
python ~/slam_ws/src/nano_slam/scripts/motor_link.py --send --port "$PORT" clear
```

这些速率单位为脉冲/秒，不能直接填米/秒。将来对接 `/cmd_vel`，还需车轮半径、轮距、整步数、细分、减速比和方向映射。目前没有把脉冲计数伪装成编码器里程计，也没有自动发布 `/odom`。

## 7. 已执行验证（2026-11-22）

Nano 上使用 g++ 7.5，以 `-std=c++11 -Wall -Wextra -Werror -pedantic` 编译 C++ 协议核心并通过原生断言测试，覆盖上电禁用、硬件未绑定、序号防重放、校验失败、限值、连续速度和点动超时、2 秒绝对上限、急停/故障锁存与毫秒计时回绕。

Python 2.7 和 Python 3.6 各通过 9 个测试，包括在伪终端上连接同一个 C++ 模拟板，执行有限点动与连续速度租约测试。Windows Python 3.13 通过 6 个主机测试，3 个需要 POSIX 伪终端的测试在 Windows 跳过；它们已在 Nano 完整运行。

这些测试只验证协议与模拟 HAL，不证明真实板卡引脚、脉冲、电机方向或实际行程正确。未打开实际 `/dev/ttyUSB1`。
